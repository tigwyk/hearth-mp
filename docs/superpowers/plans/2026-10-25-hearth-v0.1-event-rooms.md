# Hearth v0.1 (Event Rooms) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Ship roadmap milestone v0.1: wire protocol, `#[derive(HearthState)]` sync, the `Room` trait for event-mode rooms on Durable Objects, anonymous auth in a Gateway Worker, a Godot SDK (GDExtension + GDScript web fallback), a tic-tac-toe sample, and a minimal `hearth new/dev/deploy` CLI.

**Architecture:** The room runtime is pure Rust behind a `Host` trait (sockets, SQL, alarm, clock), so all room behaviour is tested natively in `hearth-test`. A thin `workers-rs` adapter implements `Host` on a hibernating Durable Object. State sync works by diffing: before and after each handler, the runtime builds each client's *view* (sync fields only, owner fields filtered) as a `serde_json::Value` tree, and sends the diff as `PATCH` ops. Since nothing per-client lives in memory, a hibernated room can always rebuild its views from SQLite.

**Tech Stack:** Rust (edition 2021), `worker` (workers-rs) on `wasm32-unknown-unknown`, `serde`, `serde_json`, `rmp-serde`, `syn`/`quote` (derives), `hmac`+`sha2`+`base64` (gateway), `rusqlite` with `bundled` (test harness only), `godot` (godot-rust gdext), wrangler/workerd for local dev and deploy.

**Spec:** [`Hearth a Rust framework for Durable Object game servers.md`](../../../Hearth%20a%20Rust%20framework%20for%20Durable%20Object%20game%20servers.md)

## Global Constraints

- Licence: every crate is `license = "MIT OR Apache-2.0"`. Add `LICENSE-MIT` and `LICENSE-APACHE` at the root.
- Server API is Rust only. JS exists only as the shim that `worker-build` generates.
- Hibernation is the default: rooms accept sockets only through the hibernation API (`state.accept_web_socket`). Never use `ws.accept()`.
- Keepalive never wakes a room: the text frame `hearth:ping` gets the DO auto-response `hearth:pong`.
- Encoding: a binary frame is 1 opcode byte followed by MessagePack. A JSON-mode frame is a text frame. The encoding of the client's `HELLO` sets the encoding for that socket.
- Max incoming frame: 64 KiB (`MAX_FRAME_BYTES = 65536`), checked before any deserialisation.
- Schema hash mismatch is a hard reject, and the error message says which hash is which.
- The client SDK batches intents into one message per frame (incoming messages are what Cloudflare bills). Defaults: at most 20 messages/s and at most 32 intents per message.
- Pin `worker` and `godot` to their latest stable releases on the day Task 1 starts. MSRV = the pinned `worker` crate's MSRV. Godot ≥ 4.3.
- Workers APIs named in this plan (`accept_web_socket`, `serialize_attachment`, `set_websocket_auto_response`, `storage().sql()`, `set_alarm`, `delete_all`, `get_stub_with_location_hint`) must be checked against the pinned `worker` version (use Context7 `/cloudflare/workers-rs`). If a name has changed, use the current name and keep the behaviour.
- **Out of scope for v0.1** (each one is a later plan): ticked mode (v0.4), handoff (v0.5), reconnect with ring buffer (v0.2), codegen and typed classes (v0.2), Unity (v0.2), admin Worker (v0.2), Matchmaker/Lobby/Player/Leaderboard DOs and `ctx.call` (v0.3), JWT/Steam/itch/Discord auth (v0.3), gateway IP rate limiting (v0.3), `hearth cost` (v0.3), `#[sync(team)]` and custom visibility predicates, R2 archive on dispose, the held-future lint, Godot editor dock, a no_std build of `hearth-protocol`, and generated DO migrations on schema change.
- Crate names may collide on crates.io (this is an open question in the spec). Do not publish in this plan.

## Review Focus

1. **Forged identity.** A client sends its own `X-Hearth-Player-Id` header, or a tampered or expired token. The gateway must return 401 for a bad token and must *overwrite* the header with the verified ID. Tests are in Task 8.
2. **Handler fails after partial mutation.** `on_intent` mutates state, queues an event and a timer, then returns `Err`. The client must get `ERROR INTENT_REJECTED`, with no patch, no event, no timer, and no change to persisted state. Tests are in Task 5.
3. **JSON clients lose u64 precision.** GDScript and JS parse JSON numbers as f64. For this reason the schema hash is a 16-char hex string and is never a number. Test is in Task 1.
4. **Same player opens a second socket** (two tabs, or a fast reconnect before close arrives). The old socket closes with 4009 `REPLACED`. The seat is kept. `on_join` and `on_leave` are not called again. Tests are in Task 6.
5. **Redeploy with an incompatible `State`.** Persisted bytes no longer deserialise. The room must not crash-loop and must not wipe data: every `HELLO` gets `ERROR STATE_INCOMPATIBLE` and close 4007, and the storage stays untouched. Tests are in Task 6.

## Deferred from the spec (not in this plan)

Each of these is listed under Global Constraints as out of scope and belongs to the roadmap milestone shown there. The v0.1-specific simplifications that a later plan may revisit are:
- The diff-based sync is O(clients × state) per message (`// shortcut:` comment on `diff`'s linear key lookup). Tracked `SyncMap` mutations can replace it for ticked mode without an API change.
- The schema hash does not include `Intent`. An intent mismatch shows up as `BAD_INTENT`, not as a silent desync.
- The schema hash ignores serde renames.

Deliberate deviations from the plan (all documented in code):

- `Host` gained `sql_handle(&self) -> Rc<dyn Sql>` so `Ctx<R>` is lifetime-free and user code writes `Ctx<Self>` as the plan specifies; `Ctx` owns the handle and `Ctx::sql()` still returns `&dyn Sql`.
- The `hearth` facade re-exports `anyhow` so room code does `use hearth::anyhow;` and calls `anyhow::bail!` without a direct dependency (the plan says users need only `hearth`, `serde` and `worker`).
- `hearth-cli` uses `src/lib.rs` plus two auto-discovered bins (`src/bin/hearth.rs`, `src/bin/cargo-hearth.rs`) instead of pointing two `[[bin]]` targets at one `src/main.rs`: this keeps both command names and removes a Cargo manifest warning.
- The DO wrapper generated by `#[hearth::room]` lives in a hidden module that imports `::worker::wasm_bindgen as wasm_bindgen` because worker 0.8.7 / wasm-bindgen 0.2.129 emit bare `wasm_bindgen` paths in the struct marker; user crates therefore do not need `use worker::*;`.
- `wrangler.toml` and the CLI template set `main = "build/worker/shim.mjs"` (the plan omitted `main`; worker-build's output requires it), and generated projects use `crate-type = ["cdylib", "rlib"]`.
- `hearth-godot` uses `crate-type = ["cdylib", "rlib"]`, `godot` feature `api-4-3` and `compatibility_minimum = "4.3"`; it adds a 3-line `hearth_plugin.gd` EditorPlugin (plugin.cfg requires a script) and a `device_id_override` test seam for two clients on one machine.
