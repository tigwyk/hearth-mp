# Hearth v1.0a (Freeze: Protocol, Conformance, API Stability, Bundle Budget) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Hearth safe to promise stability for. This plan covers:
- a normative, versioned protocol spec and schema-document spec;
- a language-neutral conformance kit with a native reference server, so third-party SDKs (Defold, Bevy, web) can verify themselves without Cloudflare;
- forward-compatibility rules that every SDK enforces;
- checked API snapshots for every public surface (Rust crates, the C ABI, GDScript, C#);
- a measured Wasm bundle-size budget, which closes the spec's open question.

**Architecture:** This plan adds almost no new runtime code. It consolidates and pins what exists. The v0.x fixtures move into one `conformance/vectors/` tree that every SDK's tests load, with hard failure when a file is missing. A small `hearth-conformance-server` runs the real `RoomRuntime` over tokio WebSockets, hosting a built-in conformance room that is driven by scripted scenarios. Stability is enforced mechanically: `cargo public-api` and `cargo semver-checks` for Rust, `cbindgen --verify` for the C ABI, and reflection-based snapshot tests for C# and GDScript. All of them run under one `scripts/check-stability.sh`.

**Tech Stack:** As before, plus dev tools `cargo-public-api` and `cargo-semver-checks`, and `tokio` + `tokio-tungstenite` for the conformance server.

**Spec:** [`Hearth a Rust framework for Durable Object game servers.md`](../../../Hearth%20a%20Rust%20framework%20for%20Durable%20Object%20game%20servers.md), sections Wire protocol ("specified independently of the Rust code so third-party SDKs (Defold, Bevy, web) can implement it"), Roadmap v1.0 ("Protocol frozen, semver guarantees"), and Open questions (Wasm bundle size). **Builds on:** every earlier plan. Names this plan does not redefine are as defined there.

## Global Constraints

- All earlier Global Constraints still apply.
- The protocol stays **version 1**. Freezing means: from now on, only *additive* changes are allowed within v1. These are new optional fields, new `EVENT` names under `hearth.`, new error codes, new close codes in `4011–4099`, and new opcodes that clients ignore. Anything else needs protocol v2.
- Forward-compatibility rules, normative for every SDK:
  - Ignore unknown object fields.
  - Ignore unknown `EVENT` names (passing them to the app is allowed).
  - Ignore frames with unknown opcodes, with no error and no close.
  - Treat unknown `ErrorCode` strings as a generic error.
  - Treat unknown close codes in `4000–4999` as fatal (no reconnect), and other unknown codes by the existing policy.

  Servers keep rejecting unknown opcodes with `BAD_FRAME`.
- Pre-1.0 compatibility shims are removed: v0.1 tokens without `prv` are rejected (24 h TTL, so this only affects stale sessions).
- Bundle flags must not change behaviour. Use `opt-level = "z"`, `lto = true` and `codegen-units = 1` in the release profile. Do **not** set `panic = "abort"`: the profile is workspace-wide, and the FFI crates rely on unwinding to catch panics.
- **Out of scope** (the v1.0b plan): the docs site, publishing to crates.io, OpenUPM and the Godot Asset Library, the crate-name and trademark check, polishing the three release samples, and the Unity Asset Store licence decision. That decision belongs to the user, and v1.0b asks for it.

## Review Focus

1. **A newer server talking to an older SDK.** Extra fields, an unknown opcode, an unknown `hearth.*` event, an unknown error code, or close code 4050. Every SDK (Rust core, GDScript web client, the C# client, plus the native Godot and Unity paths through the core) must keep working or give up cleanly, with no desync, crash or reconnect loop. Tests are in Task 3.
2. **Fixture moves silently skipping tests.** A loader that returns an empty list when a path is wrong would turn every conformance test into a pass. Every loader must fail when the file is missing or holds zero cases. Tests are in Task 2.
3. **API breaks slipping through.** Any change to a Rust public API, the C header, the C# public surface or the GDScript public surface must fail `check-stability.sh` until the snapshot is regenerated on purpose. Tests are in Task 4.
4. **`#[non_exhaustive]` added during the audit breaking our own samples and templates.** Every example, template and the CLI-generated project must still build. Tests are in Task 4.
5. **Size flags changing behaviour.** After switching profiles, the full e2e suites (tic-tac-toe, arena soak smoke, fleet handoff) must pass unchanged, and the FFI panic tests must still catch panics. Tests are in Task 5.

### Task 1: Normative protocol, schema and stability specs

**Files:**
- Create: `spec/protocol-v1.md`, `spec/schema-v1.md`, `spec/stability.md`
- Modify: `docs/protocol.md` (it becomes a one-paragraph pointer to `spec/protocol-v1.md`)
- Test: `crates/hearth-protocol/tests/spec_tables.rs`

**Interfaces:**
- Consumes: every frame, op, error code, close code and reserved event defined from v0.1 to v0.5, and `SchemaDoc` (v0.2a).
- Produces:
  - `spec/protocol-v1.md` uses RFC 2119 wording. Sections:
    1. Transport: WebSocket, binary vs text framing, the 64 KiB limit, keepalive text frames.
    2. Encoding: the opcode byte plus named MessagePack, and the JSON mode; state values are JSON data types only and map keys are strings.
    3. The opcode table.
    4. Every frame with every field, marked required or optional, including `tick` and `t`.
    5. The handshake and the schema hash check.
    6. Intents, batching and `ACK` semantics, in event and ticked mode.
    7. Patch ops with exact semantics, citing `conformance/vectors/patch.json` as normative.
    8. The error code table.
    9. The close code table (4000–4010 assigned, 4011–4099 reserved, 4100–4999 for apps).
    10. Reserved events (`hearth.handoff`, `hearth.handoff_ended`) and their payloads.
    11. Reconnect: the server holds seats, and the client policy is SHOULD, citing `reconnect.json`.
    12. Forward-compatibility rules (copied verbatim from Global Constraints).
    13. The HTTP gateway surface clients use (`/auth/*`, `/rooms`, `/match`, `/lobby`, `/me`, `/schema`), with status codes.
    14. Change policy.

    Section 13 is in scope because a third-party SDK needs it.
  - `spec/schema-v1.md`: the `SchemaDoc` JSON format (`hearth_schema: 1`), every `TypeRef`, `TypeDef`, `Shape` and `Vis` form, with one worked example (the tic-tac-toe doc, copied from the generated output), and the serde external-tagging rule for intents. It also states that the schema hash is opaque and that only equality matters.
  - `spec/stability.md` says what semver covers:
    - the Rust public APIs of the crates listed in `api/`;
    - protocol v1;
    - SchemaDoc v1;
    - the C ABI symbols and struct layouts in `api/hearth_unity.h`;
    - the GDScript and C# public surfaces in their snapshots.

    It also says what is *not* covered: `#[doc(hidden)]` items, internal `/__hearth/*` paths, SQL table layouts (only through migrations), and log line formats. Plus the MSRV policy (bumps only in minor releases, at most to stable−2) and the deprecation policy (one minor release with `#[deprecated]` before removal in the next major).
  - `spec_tables.rs` keeps the spec and the code in sync. It parses the opcode, error-code and close-code tables out of `spec/protocol-v1.md` (they are Markdown tables) and asserts that they equal the Rust definitions: `Opcode` values, every `ErrorCode` serde name, and every `close::*` constant.

### Task 3: Forward compatibility in every SDK, and the reference conformance server

**Files:**
- Modify: `crates/hearth-protocol/src/codec.rs` (`ProtocolError::UnknownOpcode(u8)`), `crates/hearth-client/src/lib.rs`
- Modify: `godot/addons/hearth/hearth_web_client.gd`, `unity/com.hearth.client/Runtime/HearthClient.cs` (C# only dispatches events, so ignoring unknown names there is enough; frames are handled by the core)
- Create: `conformance/vectors/forward.json`, `conformance/scenarios/{handshake,schema_mismatch,intents_and_acks,batching,owner_visibility,reconnect_resume,room_full,forward_compat}.json`
- Create: `crates/hearth-conformance-server/Cargo.toml` (deps: `hearth-server`, `hearth-sync`, `hearth-test` (for the rusqlite `Sql`), `tokio` with rt-multi-thread/macros/net/time, `tokio-tungstenite`, `serde_json`), `src/main.rs`, `src/room.rs`, `src/host.rs`
- Create: `crates/hearth-conformance-server/tests/scenarios.rs`, `examples/tictactoe-godot/tests/scenario_runner.gd`, `unity/com.hearth.client/Tests/Runtime/ScenarioTests.cs`
- Modify: `crates/hearth-gateway/src/auth.rs` (drop the missing-`prv` compatibility)

**Interfaces:**
- Consumes: Task 2's vectors, `RoomRuntime`, `Host`, and the rusqlite `Sql` from `hearth-test`.
- Produces:
  - `decode` returns `Err(ProtocolError::UnknownOpcode(b))` for an unknown first byte, and for a JSON `op` that is unknown. `ClientCore::handle` treats `UnknownOpcode` as `Ok(vec![])`. `RoomRuntime` keeps answering it with `BAD_FRAME`.
  - `ClientCore` maps an unknown `ErrorCode` string to `ClientEvent::Error { code: ErrorCode::Unknown(String) }`. Add an `Unknown(String)` variant with `#[serde(other)]`-style handling: implement it through a custom `Deserialize`, because `#[serde(other)]` cannot carry data. `ReconnectPolicy` already treats every `4000–4999` code as fatal. Add a fixture case for code 4050.
  - `forward.json` uses the `frames.json` shape plus `"expect": "ignored" | {"event": ...}`. Cases:
    - `PATCH` with an extra field `"z": 1` (applies normally);
    - `JOIN_OK` with an extra field;
    - a binary frame with opcode `0x40`, and a JSON frame with `"op":"FUTURE"` (both ignored);
    - `EVENT` `hearth.future` (delivered as a generic event or ignored, both allowed);
    - `ERROR` with code `"FUTURE_CODE"` (a generic error).
  - Conformance room `Conf` (in `src/room.rs`, using the same macros as user rooms; `mode = "event"`, `max_clients = 2`, `reconnect_grace_secs = 5` to keep tests fast):
    - State `{ #[sync] n: i64, #[sync] seats: SyncMap<PlayerId,u8>, #[sync(owner)] secret: SyncMap<PlayerId,String> }`
    - Intents `Add(i64) | SetSecret(String) | Echo(String) /*sends EVENT "echo"*/ | Fail | Future /*sends the forward.json frames verbatim*/`
  - `TokioHost` implements `Host` over `tokio-tungstenite` sockets, with an in-memory rusqlite `Sql`, the system clock, alarms on `tokio::time::sleep_until`, and `call` returning `Unreachable`. One `RoomRuntime` per room name, behind a `tokio::sync::Mutex`.
  - CLI: `hearth-conformance-server [--port 8790]`. It serves `ws://127.0.0.1:8790/rooms/conf/<name>?player=<id>` (no auth: a local test server only, documented as **never for production**), plus `GET /schema/conf`.
  - A scenario file is `{ "name", "clients": ["a","b"], "steps": [ {"client":"a","send": <frame JSON> | "connect" | "close"}, {"client":"b","expect": <frame JSON pattern>} , {"wait_ms": n} ] }`. A pattern matches when every field it gives is equal, `"*"` matches any value, and ops lists must match exactly. Each runner drives its SDK through its public API, or the core API for Rust, and asserts the expectations in order.
  - Runners:
    - Rust (`tests/scenarios.rs`) starts the server in-process on a random port and runs `ClientCore` over `tokio-tungstenite`.
    - GDScript (`scenario_runner.gd`) uses the **web** client, so it checks the pure-GDScript path. Run it twice: with `HEARTH_FORCE_WEB=1` for GDScript, and once natively for the GDExtension.
    - C# (`ScenarioTests.cs`, PlayMode) uses `HearthClient`.

    Each runner reads `HEARTH_CONFORMANCE_URL` and fails, not skips, when it is unset and the env var `HEARTH_REQUIRE_CONFORMANCE=1` is set.

  - `crates/hearth-client/tests/forward.rs`: every `forward.json` case through `ClientCore` (Review Focus 1).
  - `crates/hearth-conformance-server/tests/scenarios.rs`: every scenario.
  - Remove the v0.3b test `v1_token_without_prv_is_anon` and add `token_without_prv_rejected`.

### Task 4: API audit, `#[non_exhaustive]`, sealing, and stability snapshots

**Files:**

**Interfaces:**
- Consumes: every crate, the C ABI, and the C# and GDScript surfaces.
- Produces:
  - Audit rules, applied to every `pub` item of the crates in `spec/stability.md`:
    1. `#[non_exhaustive]` on enums expected to grow: `ErrorCode`, `ClientEvent`, `HandoffEvent`, `ServerReport`, `Leave`, `Mode`, `CallError`, `ProviderError`, `HandoffError`, `RoomReport`, `TypeRef`, `Shape`. **Not** on wire-frozen enums: `PatchOp` and `Frame` stay exhaustive, because adding a variant there is a protocol v2 change.
    2. `#[non_exhaustive]` on config structs users build with literals (`ClientConfig`, `ReconnectPolicy`, `HandoffRequest`, `GatewayConfig`, `AuthConfig`, `JwtConfig`, `SteamConfig`, `DiscordConfig`, `Limits`, `RoomRoute`, `PlayerRoute`). Give each one a constructor or `Default` plus builder methods, so users can still build them.
    3. Seal `Host` with the supertrait `hearth_server::__private::Sealed`, declared in a `#[doc(hidden)] pub mod __private`. `hearth-server` (`WorkerHost`), `hearth-test` (`MemHost`) and `hearth-conformance-server` (`TokioHost`) implement it. It is a soft seal: other crates technically can implement it, but it is hidden and excluded from semver by `spec/stability.md`. A hard seal would block the two sibling crates. The users of `Host` are internal. `Room`, `Service`, `RoomRpc`, `Logic`, `Allocator` and `Fetcher` stay open, because users implement them.
    4. Items that exist only for macros or tests become `#[doc(hidden)]` (the `ffi::__impl_*` functions, macro support types).
    5. Every public item has a doc comment. Enforce `#![warn(missing_docs)]` per crate and fix the warnings.
  - `scripts/check-stability.sh` runs these, and exits non-zero on any diff with the message `"API changed: review, then run scripts/check-stability.sh --bless"`. `--bless` rewrites the snapshots.
    - For each crate in a fixed list: `cargo public-api -p <crate> --simplified` vs `api/<crate>.txt`.
    - `cargo semver-checks check-release --baseline-rev <last tag>`, skipped with a printed note until a first tag exists.
    - `cbindgen --verify` plus a diff of `include/hearth_unity.h` against `api/hearth_unity.h`.
    - The Unity EditMode `ApiSnapshotTests`, which reflect over the `Hearth.Client` assembly's public types and members, sorted, into text compared with `api/unity-csharp.txt`. The test writes the new text to `Temp/` on a mismatch.
    - The Godot `api_snapshot.gd`, which lists, for each addon script, `class_name`, public methods with their argument names, and signals with their arguments, compared with `api/godot-gdscript.txt`. Names starting with `_` are excluded.
