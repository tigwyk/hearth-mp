# Hearth v0.2a (Reconnect + Godot Codegen) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Dropped clients get their seat back within a grace window, and Godot devs get typed, signal-emitting state classes plus typed intent helpers generated from the server crate by `hearth codegen --godot`.

**Architecture:** On socket close the runtime *holds* the seat in SQLite and starts a durable grace timer. A held seat is keyed by the gateway-authenticated `PlayerId`, so resume needs no extra token. A resumed client gets a fresh `FULL_STATE`. On the client, a sans-IO reconnect policy in `hearth-client`, mirrored in GDScript, drives retries in both Godot backends. For codegen, the `Schema` derive also emits a machine-readable type description. A test that the room macro emits writes it to JSON, and the CLI turns that JSON into GDScript classes. These classes are thin metadata over one shared typed-mirror runtime (`hearth_typed.gd`), which reloads the affected subtree after each patch op and emits only the signals whose values changed.

**Tech Stack:** As in v0.1. No new crates. GDScript for the typed runtime.

**Spec:** [`Hearth a Rust framework for Durable Object game servers.md`](../../../Hearth%20a%20Rust%20framework%20for%20Durable%20Object%20game%20servers.md). **Builds on:** [`2026-10-25-hearth-v0.1-event-rooms.md`](2026-10-25-hearth-v0.1-event-rooms.md). Every name, file and constant this plan does not redefine is as defined there.

## Global Constraints

- All v0.1 Global Constraints still apply.
- Reconnect grace: default **30 s**, seat held for that time (spec). Configure it with `#[hearth::room(reconnect_grace_secs = N)]`. `0` restores the v0.1 behaviour (`on_leave(Closed)` at once).
- Codegen output: `hearth codegen --godot` emits GDScript classes with **a signal per field**. The usage shape is `Hearth.state.marks.item_added.connect(...)` (spec).
- A schema change must change the hash, so stale clients fail loudly. From this plan on, the hash covers the `Intent` type too.
- Protocol stays at `PROTOCOL_VERSION = 1`. This plan changes no frames.
- **Deliberate deviations from the spec**, each with its reason:
  - **No reconnect token in `JOIN_OK`.** The gateway already authenticates the `PlayerId` that keys the held seat, so a second secret would add nothing.
  - **No missed-patch ring buffer.** A resume always gets `FULL_STATE`. The spec allows "either ... or". Outgoing messages are free, and the typed mirror turns a `FULL_STATE` into minimal signals anyway. Revisit this when state sizes grow (v0.4).
- **Out of scope** (each has its own plan): Unity package, C# codegen and the "local server" toggle (v0.2b), admin Worker (v0.2c), Godot editor dock.

## Review Focus

1. **Drop → hibernation → resume inside the grace window.** The client must get the same seat and `FULL_STATE`, with no `on_leave` or `on_join` call. After the grace window it must be a fresh join. Tests are in Task 1.
2. **Intents in flight when the socket drops.** The server may or may not have applied them. The client must report them as `IntentsUnconfirmed` and never resend them silently. Queued intents that were never sent must wait for `JOIN_OK`. Tests are in Task 2.
3. **Fatal close codes must not retry.** A stale build that gets 4001 `SCHEMA_MISMATCH` and keeps reconnecting would bill a request each time, forever. Every `4000–4999` code and `1000` must give up at once. Tests are in Task 2, and the same fixture is checked in Task 3.
4. **Names that break GDScript.** A Rust field named `class`, `func` or `signal`, a field that collides with a base-class member, or two Rust types with the same name in different modules. Codegen must escape the first two and fail with a clear message on the third. Tests are in Tasks 4 and 7.
5. **`#[serde(...)]` attributes that change the wire shape** (`rename`, `rename_all`, `tag`, `untagged`, `flatten`, `skip*`, `content`). These would silently desync the typed clients, so they must be a compile error. Tests are in Task 4.

### Task 6: Godot typed-mirror runtime (`hearth_typed.gd`)

**Files:**
- Create: `godot/addons/hearth/hearth_typed.gd`
- Modify: `godot/addons/hearth/hearth_client.gd`
- Create: `examples/tictactoe-godot/tests/typed_fixture/` (hand-written classes in the exact Task 7 output format, used only by this test), `tests/typed_runtime.gd`

**Interfaces:**
- Consumes: the `PatchOp` JSON shape, the raw `state` Dictionary that both backends already maintain, and `StateReset` / `patched(ops)`.
- Produces (the contract Task 7 generates against):
  - `class_name HearthObject extends RefCounted`. A generated subclass defines `static func _hearth_meta() -> Dictionary` and typed `var`s. The base class provides `func _hearth_load(raw: Dictionary) -> void`.
  - `class_name HearthMap extends RefCounted` with signals `item_added(key: String, value)`, `item_removed(key: String)`, `item_changed(key: String, value)`, and methods `get_item(key)`, `has(key) -> bool`, `keys() -> Array`, `size() -> int`. Values are typed instances or plain variants.
  - `class_name HearthList extends RefCounted` with signal `changed()` and methods `at(i)`, `size() -> int`, `to_array() -> Array`.
  - `class_name HearthEnum extends RefCounted` with `var variant: String` and `var value` (null for unit variants; a typed value or Array otherwise).
  - Meta format: `{"fields": [{"gd": String, "wire": String, "ty": <TypeRef as JSON> }], "types": {<Rust type name>: <class script>}}`, plus, for enums, `{"variants": [{"name", "shape"}]}`. A `TypeRef` `Named(n)` resolves through `types[n]`.
  - Reload semantics (`_hearth_load`):
    - Leaf, enum, option, tuple or array field: assign, and `emit_signal(gd + "_changed", value)` only when the raw value differs (`!=`).
    - Object field: reuse the existing instance and recurse.
    - Map: emit `item_removed` for keys that are gone and `item_added` for new keys. For a key in both whose raw value differs, reload in place (objects) or assign, then emit `item_changed`.
    - List: if the raw value differs, rebuild and emit `changed`.
    - Instances are kept across reloads, so UI code can hold `state.marks.get_item(id)`.
  - `static func route(root: HearthObject, raw_root: Dictionary, op: Dictionary) -> void`: let the container path be `op.path` for `map_insert`/`list_splice` and `op.path[:-1]` for `set`/`del`. Walk the typed tree along it to the deepest typed node (object, map or list) and reload that node from the matching raw subtree.
  - `Hearth` autoload:
