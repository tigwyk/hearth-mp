# Hearth v0.5 (Handoff) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A room can hand its players to a dedicated server, either a Cloudflare Container or the dev's own fleet, through a ticket API. The room stays in charge of the session state and the results, and Hearth bills only for the coordination.

**Architecture:** `ctx.handoff(...)` records a *session* and an allocation job in the room's SQLite, as part of the handler's commit. The DO adapter runs the allocation **outside** the runtime lock: an HMAC-signed webhook to the dev's allocator, or a start call to a per-session Container DO. A slow start therefore never stalls the room. On success, each player receives a private `hearth.handoff` event with the endpoint and a single-use, 60-second ticket. Dedicated servers authenticate with a per-session secret: they redeem tickets and report lifecycle events (`started`, `heartbeat`, `player_joined`/`left`, `result`, `ended`) over HTTPS to the gateway, and the room receives these through `on_handoff`. For Containers, the gateway redeems the ticket itself and proxies the player's WebSocket to the container with identity headers. Tickets are random IDs checked online, so no game server needs crypto code and every redemption is single-use.

**Tech Stack:** As before, plus Cloudflare Containers (Docker; supported by `wrangler dev` locally). The Rust server SDK uses `ureq`. The container sample uses `tokio` and `tokio-tungstenite`.

**Spec:** [`Hearth a Rust framework for Durable Object game servers.md`](../../../Hearth%20a%20Rust%20framework%20for%20Durable%20Object%20game%20servers.md), sections Target games (Handoff row and the hard line), Architecture ("Handoff-mode rooms issue a ticket to a dedicated server and stay involved only for session state"), and Roadmap v0.5. **Builds on:** every earlier plan. Names this plan does not redefine are as defined there: `Ctx`, `RoomRuntime`, the outbox, `Fetcher`, `CannedFetcher`, `TestWorld`, `GatewayConfig`, `notify`, `ClientEvent::Event`, and the v0.3a Player stats.

## Global Constraints

- All earlier Global Constraints still apply.
- Handoff is used for shooters, fighting games and physics-heavy action: anything needing more than about 20 Hz authoritative simulation, UDP, or more than about 100 MB of live state (spec). The room handles matchmaking and session state, and issues tickets. The dedicated server runs on Cloudflare Containers or the dev's own fleet (spec).
- **A handoff is a room capability, not a third `mode`.** The spec's table lists Handoff as a mode, but the room part of a handoff is plain event-mode coordination (lobby, ready-up, results). Any event or ticked room can call `ctx.handoff`, and `mode = "handoff"` is a compile error pointing at `ctx.handoff` (the message is in Task 1). This changes the v0.1 macro error text.
- No UDP or WebRTC through Hearth (spec non-goal for v1). Container endpoints are WebSocket through the gateway. Fleet endpoints are whatever the allocator returns (UDP included), because Hearth only hands out the address.
- Tickets: 32 random hex characters, single-use, a 60 s TTL, and bound to one `(session, player)`. The room stores only the SHA-256 of each ticket.
- The session secret is 32 random bytes as hex, generated per session. Only its SHA-256 is stored. It is sent once to the allocator or container and never to clients.
- Timeouts, with defaults set on `HandoffRequest`: start 60 s (server must report `started`), heartbeat 60 s (some report at least that often), max duration 2 h.
- Event names starting with `hearth.` are reserved for the framework. `ctx.send` and `ctx.broadcast` drop such names and log `reserved_event_name`.
- **Out of scope:** Agones, Edgegap or Hathora-specific allocators (the generic webhook covers them; docs show the mapping), UDP through Cloudflare, Unity prediction (v0.4b), and the v1.0 protocol freeze.

## Review Focus

1. **Ticket replay and theft.** A ticket redeemed twice, after 60 s, by a different session's secret, or for a different player than the one it was minted for. Every such case must fail with 403/410, without saying which check failed. Tests are in Task 1.
2. **A compromised server forging another session's results.** Reports require that session's secret (constant-time compare against the stored hash). Reports after `ended` or `failed` are ignored. Tests are in Tasks 1 and 2.
3. **Slow, failing or interrupted allocation.** The room keeps answering intents while a container takes 20 s to start. Eviction mid-allocation retries with the same `sid` as the idempotency key, so one session never gets two servers. After 3 attempts, `on_handoff(Failed)` fires and no tickets are issued. Tests are in Tasks 2 and 3.
4. **A server that dies silently.** With no heartbeat for 60 s, the session becomes `Failed { reason: "lost" }`, the container is stopped, the room becomes disposable again, and the players get `hearth.handoff_ended`. Tests are in Tasks 1 and 3.
5. **Allocator response used as a weapon.** The endpoint returned to clients must match `^(udp|wss|https)://[^\s]{1,250}$` (plus `ws://` only when `allow_insecure_endpoints` is set for local dev). Claims come only from the room, never from the allocator or a client. The allocator URL comes only from config. Tests are in Task 2.

**Interfaces:**
- Consumes: the handler pass and effect buffer, the timers, the empty-room logic, and the attachment/client model.
- Produces:
  - `pub struct HandoffRequest { pub players: Vec<PlayerId>, pub claims: Value, pub region: Option<String>, pub start_timeout: Duration /*60s*/, pub heartbeat_timeout: Duration /*60s*/, pub max_duration: Duration /*2h*/ }` with a builder: `HandoffRequest::new(players, claims)`.
  - `Ctx::handoff(&mut self, req: HandoffRequest) -> SessionId` is buffered like any other effect, so a failed handler creates nothing. It returns the ID at once. Every player in `req.players` must be seated, or the request is dropped and logged as `handoff_unknown_player`.
  - `#[derive(Serialize, Deserialize, Clone, PartialEq, Eq, Hash, Debug)] pub struct SessionId(pub String)`. The value is `"hs_" + b64url_nopad("{room_type}/{name}") + "_" + 16 hex`, so the gateway can route on it alone.
  - Tables:
    - `hearth_sessions (sid TEXT PRIMARY KEY, status TEXT NOT NULL /*allocating|ready|started|ended|failed*/, secret_hash BLOB NOT NULL, players TEXT NOT NULL /*JSON*/, claims TEXT NOT NULL, region TEXT, endpoint TEXT, attempts INTEGER NOT NULL, created_ms INTEGER, deadline_ms INTEGER /*next timeout*/, ended_ms INTEGER)`
    - `hearth_tickets (hash BLOB PRIMARY KEY, sid TEXT NOT NULL, player_id TEXT NOT NULL, exp_ms INTEGER NOT NULL, used INTEGER NOT NULL)`
  - `pub struct AllocJob { pub sid: SessionId, pub secret: String /*plaintext, held only in memory until allocated*/, pub room: RoomName, pub players: Vec<PlayerId>, pub claims: Value, pub region: Option<String>, pub attempt: u32 }`. The plaintext secret is regenerated if the isolate restarts before allocation; since the server has not received it yet, nothing is lost. Each regeneration updates `secret_hash`.
  - `RoomRuntime` gains these methods:
    - `fn take_jobs(&mut self) -> Vec<AllocJob>`: sessions in `allocating` whose job is not in flight. A job returned here is in flight until `job_done` or 30 s pass. After 30 s it is returned again with `attempt + 1`.
    - `async fn job_done(&mut self, sid: &SessionId, r: Result<String /*endpoint*/, String /*error*/>)`:
      - On `Ok`: set the status to `ready`, store the endpoint, mint one ticket per player, and send each player a private `EVENT { name: "hearth.handoff", data: {"sid","endpoint","ticket","expires_ms"} }` (only to that player's socket). Then set the deadline to now + `start_timeout`, and run `on_handoff(Ready { endpoint })`.
      - On `Err`: when `attempt < 3`, keep `allocating` (it is retried after a 2^attempt s backoff through `next_wake`). Otherwise set `failed` and run `on_handoff(Failed { reason })`.
    - `async fn redeem(&mut self, sid: &SessionId, secret: &str, ticket: &str) -> Result<Redeemed, HandoffError>`
    - `async fn report(&mut self, sid: &SessionId, secret: &str, ev: ServerReport) -> Result<(), HandoffError>`
    - `async fn redeem_trusted(&mut self, sid: &SessionId, ticket: &str) -> Result<Redeemed, HandoffError>`: for the gateway's container proxy, with no secret.
    - `fn reissue_ticket(&mut self, sid, player)`: sends a fresh `hearth.handoff` to a player who reconnected to the room while the session is `ready` or `started`.
  - `pub struct Redeemed { pub player_id: PlayerId, pub provider: String, pub display_name: Option<String>, pub claims: Value, pub sid: SessionId }`
  - `#[serde(tag = "type", rename_all = "snake_case")] pub enum ServerReport { Started, Heartbeat, PlayerJoined { player: PlayerId }, PlayerLeft { player: PlayerId }, Result { data: Value }, Ended { reason: String } }`
  - `pub enum HandoffError { NotFound /*404*/, Forbidden /*403: bad secret, wrong session, used or expired ticket*/, Gone /*410: session ended or failed*/ }`. The single `Forbidden` hides which check failed (Review Focus 1).
  - `Room` gains `async fn on_handoff(&mut self, ctx: &mut Ctx<Self>, sid: &SessionId, ev: HandoffEvent) -> Result<()> { Ok(()) }`, where `pub enum HandoffEvent { Ready { endpoint: String }, Started, PlayerJoined(PlayerId), PlayerLeft(PlayerId), Result(Value), Ended { reason: String }, Failed { reason: String } }`. Every server report (except `Heartbeat`) and every timeout becomes one handler pass.
  - Timeouts through `next_wake`:
    - `ready` without `started` past `start_timeout` → `failed("start timeout")`.
    - `started` with no report for `heartbeat_timeout` → `failed("lost")`. Any accepted report moves the deadline.
    - `created + max_duration` → `failed("max duration")`.
    - A failure caused by a timeout queues a *stop job* (Task 3 uses it), and the players get `EVENT hearth.handoff_ended {sid, reason}`. `ended` does the same.
  - Lifecycle: a session in `allocating`, `ready` or `started` counts as "not empty" for the empty-room timer. Ended and failed sessions are kept for 24 h and then pruned.
  - The macro error is: `mode = "handoff"` → `"handoff is not a room mode; call ctx.handoff(...) from an event or ticked room (see docs/handoff.md)"`.
  - Reserved names: `ctx.send`/`ctx.broadcast` with a `hearth.` name drops it and logs `reserved_event_name`.

Test room `Lobby` (event mode, `max_clients = 4`): the intent `Start` calls `ctx.handoff` for all seated players. `on_handoff` records each event's name in a `#[sync] log: Vec<String>` and stores `Result` data in `#[sync] result`.

  - `ContainerObject` handles:
    - `POST /__hearth/call` with `ContainerRpc::Start { sid, secret, report_url, port: u16 /*default 8080*/, env: BTreeMap<String,String> }`: starts the container with env `HEARTH_SID`, `HEARTH_SESSION_SECRET`, `HEARTH_REPORT_URL` and `HEARTH_PORT` plus the dev's `env`. It polls `GET http://container/healthz` on the port every 500 ms for up to 60 s, and replies `Ok(())`. A start for a `sid` that is already running replies `Ok(())`, which makes it idempotent.
    - `ContainerRpc::Stop`: destroys the container.
    - `GET|WS /__hearth/proxy/*`: forwards to the container port unchanged, headers included.
    - It also sets an alarm for `max_duration + 5 min` as a backstop that destroys the container even if the room never sends `Stop`.
  - `container_object!(Class)` defines the DO class in the user crate, like `registry_object!`.
  - `pub struct ContainerAllocator { pub binding: &'static str /*e.g. "ARENA_SERVER"*/, pub public_url: String, pub port: u16, pub env: BTreeMap<String,String> }`. `allocate` calls `Start` through the Host call path and returns `"wss://{public_url}/handoff/{sid}/connect"` (or `ws://` when `public_url` is `http://`). `stop` calls `Stop`.
  - Gateway `GET /handoff/{sid}/connect?ticket=<t>` (WebSocket):
    1. Call the room's internal `POST /__hearth/redeem_trusted` (a new internal path wrapping `redeem_trusted`; only the gateway can reach it).
    2. On success, forward the upgrade to the session's `ContainerObject` at `/__hearth/proxy/connect`, with the headers `X-Hearth-Player-Id`, `X-Hearth-Provider`, `X-Hearth-Display-Name` (percent-encoded) and `X-Hearth-Claims` (base64url JSON) set by the gateway. Any client-sent copies of these headers are removed.
    3. If the redeem fails: 403 or 410, before any upgrade.

    The binding is found from the room's route config: `RoomRoute` gains `container: Option<&'static str>`.
  - `wrangler.toml`: a `[[containers]]` entry with `class_name = "ArenaServer"`, `image = "./server/Dockerfile"` and `max_instances = 10`, the DO binding `ARENA_SERVER`, and the migration `v4` with `new_sqlite_classes = ["ArenaServer"]`.

It reads identity from the forwarded headers, reports `player_joined` per socket, runs a 5-second "match" once 2 players are in that broadcasts the server time at 30 Hz, and then reports `result` and `ended` and exits.

### Deliberate deviations

**Runtime**

- `hearth_sessions` persists the three timeout values. The plan's DDL omitted
  them, and hibernation between `allocating` and `started` would have lost them.
- Stop jobs live in an internal `hearth_stops` table (`take_stop_jobs`) instead
  of a field on a handoff type; the adapters run them next to allocation jobs.
- A successful allocation that arrives *after* the server's `started` report is
  not stale: the container reports `started` from boot and can beat the
  allocator's answer. The room records the endpoint and sends the tickets then,
  so `on_handoff` may see `Started` before `Ready` (documented).
- Duplicate `started` reports are treated as a heartbeat (no second handler
  pass). Reports after end answer `Ok`; redeem after end answers `Gone`.
- A player who reconnects to a live session gets a fresh ticket on join/resume;
  old unused tickets stay valid until their 60 s TTL.
- `mode = "handoff"` is a compile error pointing at `ctx.handoff`, and the room
  attribute grew `allocator = "webhook" | "container"` plus
  `container = "BINDING"`.

**Adapters and gateway**

- `HEARTH_PUBLIC_URL` is required by both allocator modes (both the report URL
  and the connect endpoint derive from it), not only by webhook mode.
- `HEARTH_ALLOCATOR_MODE` can override the compile-time allocator per
  deployment, so one sample serves both e2es.
- The container proxy fetches `http://container/...`: Cloudflare rejects HTTPS
  to a container port. The adapter also works around worker 0.8.7's
  `ContainerStartupOptions` conversion, which drops the env; it builds the
  documented JS options object (`env`, `enableInternet: true`) and calls `start`
  directly.
- The container backstop uses the session's own `max_duration` (piped through
  `AllocJob`) rather than a fixed 2 h default.
- The webhook 409 is treated as idempotent, but its endpoint is not compared to
  the first answer: the protocol gives a stateless receiver no way to know it.
  `docs/handoff.md` states that.

**Validation**

- Local Containers and the Godot container smoke cannot run on Windows
  (`wrangler dev` needs WSL/Linux/macOS). Both were instead run against a
  temporary deployed Worker on the existing OAuth session, then the Worker and
  container application were removed. Only `e2e-container.mjs` check 6
  (local-Docker kill path) remains unverified.
