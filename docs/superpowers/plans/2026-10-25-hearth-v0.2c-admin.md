# Hearth v0.2c (Admin + Observability) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** A dev can list live rooms, inspect any room's full server state, force-dispose a room, and tail its patches live, from `hearth inspect`, against local `wrangler dev` or production. Rooms also log their key events to Workers Logs.

**Architecture:** Durable Objects cannot be enumerated by name, so rooms report themselves to a single `HearthRegistry` DO (SQLite) when they first open, when their seated count changes, and when they are disposed. A registry failure never affects gameplay. Admin requests go through a bearer-token-gated `/admin/*` router (`hearth-admin`), which talks to rooms over internal DO paths (`/__hearth/*`). The gateway builds these paths itself, so players can never reach them. Inspect is read-only and never creates storage. A tail is a hibernatable admin WebSocket that receives unfiltered full-state diffs, each labelled with its cause.

**Tech Stack:** As in v0.1. The CLI gains `ureq` (blocking HTTP) and `tungstenite` with `rustls` (WebSocket).

**Spec:** [`Hearth a Rust framework for Durable Object game servers.md`](../../../Hearth%20a%20Rust%20framework%20for%20Durable%20Object%20game%20servers.md), section "Ops". **Builds on:** [v0.1](2026-10-25-hearth-v0.1-event-rooms.md) and [v0.2a](2026-10-25-hearth-v0.2a-reconnect-godot-codegen.md). Names this plan does not redefine are as defined there: `RoomRuntime`, `Host`, `MemHost`, `TestRoom`, `Attachment`, `Sql`, `RoomRoute`, `serve`, `hearth_held`, `diff`. v0.2b (Unity) is independent of this plan.

## Global Constraints

- All earlier Global Constraints still apply.
- Spec features: list live rooms, inspect state, force-dispose, tail patches, and Workers Logs. The CLI command is `hearth inspect`.
- **Deliberate deviation:** the spec says "a Hearth admin Worker". Here the admin is a library (`hearth-admin`) that the dev's Worker mounts at `/admin/*` **only when `HEARTH_ADMIN_TOKEN` is set**. That keeps one deploy and one set of DO bindings. `docs/admin.md` explains how to deploy the same crate as a separate Worker (`script_name` DO bindings) for teams that want isolation.
- Admin auth: `Authorization: Bearer <HEARTH_ADMIN_TOKEN>`, compared in constant time. The token must be at least 32 bytes, or the admin routes are disabled (404). Never accept the admin token in a query string.
- The registry is optional. When the `HEARTH_REGISTRY` binding is missing, rooms skip reporting and `/admin/rooms` returns `501 {"error":"HEARTH_REGISTRY binding not configured"}`. Inspect, dispose and tail still work, because they only need the room's type and name.
- Shortcut: one registry DO for all rooms. Add the code comment `// shortcut: single registry DO (~1k writes/s); shard by hash(room_type, name) when a game outgrows it`.
- **Out of scope:** an HTML admin UI (the CLI and the JSON API cover the spec's features), R2 replay archives, `hearth cost` (v0.3), and generated migrations.

## Review Focus

1. **Admin token missing, short or wrong.** With no token or a short one, every `/admin/*` path returns 404, as if the feature doesn't exist. A wrong token returns 401. Tests are in Tasks 4 and 5.
2. **The registry is down or erroring.** Joins, intents and dispose must work exactly as before. The failure only shows up in the logs. Tests are in Task 1.
3. **Inspecting a room that never existed.** Calling `id_from_name` on any name creates a DO. Inspect must answer 404 without creating any table or registry row. Tests are in Task 1.
4. **A player reaching internal paths.** Requests such as `/rooms/t/n/__hearth/dispose` or encoded `..` segments must be 404 or 400 at the gateway. The DO only receives URLs that the gateway built. Tests are in Task 4.
5. **An admin tail socket in the room.** It must never take a seat, receive player frames, or keep an empty room from disposing. It gets closed with 4008 like everyone else on dispose. Tests are in Task 2.

Force-dispose of a room in `STATE_INCOMPATIBLE` mode must work, because that is the remedy for v0.1 Review Focus 5. Tests are in Task 1.

**Interfaces:**
- Consumes: v0.1/v0.2a `RoomRuntime`, `Host`, `MemHost`, the dispose path, and the incompatible-state mode.
- Produces:
  - `#[derive(Serialize, Deserialize, Clone, Debug, PartialEq)] pub struct RoomName { pub room_type: String, pub name: String }`
  - `#[derive(Serialize, Deserialize, Clone, Debug, PartialEq)] #[serde(tag = "kind", rename_all = "snake_case")] pub enum RoomReport { Open { room: RoomName, created_ms: u64, players: u8 }, Players { room: RoomName, players: u8 }, Disposed { room: RoomName } }`. `players` counts seated players, both live and held.
  - `Host` gains `async fn report(&self, r: RoomReport) -> Result<()>`. The runtime logs an `Err` with `log_line` and otherwise ignores it.
  - `Host` gains `fn log_line(&self, json: &str)`. `MemHost` collects the lines, and `WorkerHost` calls `console_log!`.
  - `RoomRuntime::connect` becomes `connect(&mut self, s, player: PlayerId, room: RoomName)`. On the first connect ever, the runtime writes `room` and `created_ms` to `CREATE TABLE IF NOT EXISTS hearth_meta (key TEXT PRIMARY KEY, value TEXT NOT NULL)`, using the keys `room_type`, `name` and `created_ms`.
  - Reports are sent at these points: `Open` after the first successful join, `Players` after any pass where the seated count changed, and `Disposed` after the wipe (both the timer and `ctx.dispose`).
  - Log lines are JSON objects with `"hearth"` set to `"join"`, `"leave"`, `"dispose"`, `"handler_error"` or `"state_incompatible"`, plus `room`, `player` (when one applies) and `msg` (errors).
  - `#[derive(Serialize)] pub struct InspectDoc { pub room: RoomName, pub created_ms: u64, pub seq: u64, pub locked: bool, pub incompatible: bool, pub clients: Vec<InspectClient>, pub timers: Vec<(String, u64)>, pub state: Option<Value>, pub state_bytes: usize }`, where `InspectClient { player_id, seat, connected, held_until_ms: Option<u64> }`. `state` is the **full** server state as JSON, server-only fields included, and `None` when the room is incompatible.
  - `RoomRuntime::inspect(&mut self) -> Result<Option<InspectDoc>>`. It returns `Ok(None)` when `hearth_meta` does not exist. It checks `sqlite_master` first and must not run any `CREATE` or `INSERT`.
  - `RoomRuntime::force_dispose(&mut self) -> Result<bool>`. It returns `false` when the room has no `hearth_meta`. Otherwise it runs `on_dispose` when the state is compatible (an error is logged and ignored), closes all sockets with 4008, wipes, and reports `Disposed`.
  - `TestRoom` gains `reports(&self) -> &[RoomReport]`, `logs(&self) -> &[String]`, `fail_reports(&mut self, on: bool)`, `inspect(&mut self) -> Option<InspectDoc>`, `force_dispose(&mut self) -> bool`, and `room_name(&self) -> RoomName` (default `{"counter","r1"}`, passed on every connect).

**Interfaces:**
- Consumes: Task 1, plus the v0.1 handler pass.
- Produces:
  - `Attachment` gains `#[serde(default)] pub admin: bool`.
  - `RoomRuntime::connect_admin(&mut self, s: H::Socket)` sets the attachment `{admin: true}` and sends nothing. Admin sockets are excluded from seats, clients, room-full checks and the empty-room check. Their incoming messages are ignored, except that close is handled.
  - `#[derive(Serialize)] #[serde(tag = "cause", rename_all = "snake_case")] pub enum Cause { Join { player: PlayerId }, Reconnect { player: PlayerId }, Intent { player: PlayerId, intent_seq: u32 }, Leave { player: PlayerId }, Disconnect { player: PlayerId }, Timer { key: String }, Dispose }`
  - `#[derive(Serialize)] pub struct TailMsg { pub seq: u64, pub cause: Vec<Cause>, pub ops: Vec<PatchOp>, pub rejected: Vec<u32> }`. `ops` is `diff(full_before, full_after)` over the **unfiltered** full state. `rejected` lists the intent seqs that failed in this pass.

  - `TestRoom::tail(&mut self) -> C` opens an admin socket. `TestRoom::tail_msgs(&self, c: C) -> Vec<Value>` returns the parsed text frames that socket received.

  - `RoomObject::fetch` dispatches on the exact path:

    - `GET /__hearth/inspect` → `200 InspectDoc` or `404`
    - `POST /__hearth/dispose` → `204` or `404`
    - `/__hearth/tail` (WebSocket upgrade, accepted through the hibernation API, then `connect_admin`)
    - Anything else → `404`.
  - `WorkerHost::report` POSTs to `env.durable_object("HEARTH_REGISTRY")?.id_from_name("global")` at `/report`. When the binding is missing, it returns `Ok(())` without doing anything.
  - The gateway builds the DO request URL as `https://room/__hearth/connect` itself, keeps no client path or query, and sets `X-Hearth-Room`. It rejects room names that fail `valid_room_name` **after** percent-decoding. Path segments other than the exact route shapes get 404.
  - `pub fn admin_token(env: &Env) -> Option<Vec<u8>>` returns `None` when the token is unset or shorter than 32 bytes. `pub fn check_bearer(header: Option<&str>, token: &[u8]) -> bool` compares in constant time with `subtle`-style XOR folding; write it inline in about 6 lines and do not add a crate.
  - `pub async fn serve_admin(req: Request, env: Env, routes: &[RoomRoute]) -> worker::Result<Response>`:
    - `GET /admin/rooms?type=&cursor=&limit=` → the registry `list` result. `cursor` is base64url of the JSON `RoomName`. Returns 501 when the registry binding is missing.
    - `GET /admin/rooms/{type}/{name}` → proxied to `/__hearth/inspect`.
    - `POST /admin/rooms/{type}/{name}/dispose` → proxied to `/__hearth/dispose`.
    - `GET /admin/rooms/{type}/{name}/tail` (WebSocket) → proxied to `/__hearth/tail`.
    - `{type}` must be a known route (404 otherwise), and `{name}` must pass `valid_room_name` (400 otherwise).
  - The example's `#[event(fetch)]` sends `/admin/*` to `serve_admin` **only** when `admin_token(&env).is_some()`; otherwise those paths fall through to the gateway's 404. Everything else goes to `hearth_gateway::serve` as before. Add `hearth::admin::registry_object!();` to the example.
  - `wrangler.toml` gains `[[durable_objects.bindings]] name = "HEARTH_REGISTRY" class_name = "HearthRegistry"`, `[[migrations]] tag = "v2" new_sqlite_classes = ["HearthRegistry"]`, and `[observability] enabled = true`. Add `HEARTH_ADMIN_TOKEN=` with a 64-hex placeholder to `.dev.vars.example`.

### Deliberate deviations

- **Commit shape.** Tasks 1 and 2 share one commit: both live in
  `crates/hearth-server/src/runtime.rs`, so splitting them would leave a
  non-compiling intermediate commit. Task 4 is two commits (`hearth-admin` half with
  Task 3, worker/gateway/example/e2e half), preceded by one workspace-dependency
  preparation commit so each task commit stays self-contained.
- **Registry test SQL.** `hearth-admin`'s registry tests use `hearth_test::MemHost`
  (which implements `Sql`) instead of a new `hearth_test::mem_sql()`; `MemHost::sql()` was
  added as the small helper the tests needed.
- **Opaque room cursor.** `GET /admin/rooms` returns `next` as the opaque base64url
  cursor string (the server still accepts a base64url JSON `RoomName`); the CLI echoes
  it verbatim. `docs/admin.md` documents the string form.
- **No percent-decoding of the room name.** The admin router and gateway validate the
  raw `{name}` segment with `valid_room_name`, so encoded traversal (`..%2F…`) is
  rejected with 400 instead of decoded. Stricter than the plan's "after percent-decoding"
  wording, and the e2e accepts 400 or 404.
- **Token in the example files.** `.dev.vars.example` ships `HEARTH_ADMIN_TOKEN`
  commented out, so a copied example has the admin API disabled by default; the local
  (gitignored) `.dev.vars` carries a real token for dev and e2e.
- **Inspect includes internal timers** (`h:empty`, `h:grace:*`): the plan says every
  scheduled timer, and hiding the runtime's own keys would make the doc lie.
- **Dispose tail frame.** `force_dispose` sends one final `dispose` tail frame (after
  state is gone) before closing the tail with 4008, so a tail sees why it ended.
- **No-tail cost hook.** `Host::count_full_state` is the plan's "MemHost counts
  full-state `to_value` calls" hook: the runtime calls it immediately before each
  full-state render done for a tail, and `MemHost` counts it (`no_tail_no_extra_work`).
- **`hearth-admin` registry object** takes `worker::State` and uses the shared
  `hearth_server::worker::WorkerSql` rather than repeating Durable Object SQL plumbing.
- **CLI 204 handling.** ureq 3.5 fails to read the empty body of workerd's headerless
  204 (`gzip decompression failed`); the CLI skips the body for 204/205/304. Found by
  the hand test, not by the unit tests.
- **v0.2b (Unity) was skipped.** Per user instruction this session implemented the next
  plan that needs no Unity toolchain; v0.2b remains unimplemented and is independent of
  this plan.

Environment note: both e2e phases ran locally with `npx --yes wrangler@4 dev --port
8787` in `examples/tictactoe`; phase 2 temporarily removed `HEARTH_ADMIN_TOKEN` from the
local `.dev.vars` between server starts (it is not committed).
