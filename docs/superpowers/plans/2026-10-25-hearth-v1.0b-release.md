# Hearth v1.0b (Release) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1.0: a settled name, clean licensing for every shipped binary, three sample games as `hearth new` templates, a docs site, a reproducible release pipeline, and published packages on crates.io, OpenUPM and the Godot Asset Library.

**Architecture:** No new runtime code. The work is packaging, verification and gated outward actions. Everything that can be checked locally is automated: dry-runs, version consistency, licence audits, and builds of the generated templates. Everything that is irreversible or public (picking the name, publishing, deploying the docs site, submitting to stores) is a **stop-and-ask step for the user**. The plan prepares each such action so that, once approved, it is one command or one form.

**Tech Stack:** As before, plus `mdbook`, `cargo-deny`, `cargo-about`, `git-cliff` and `include_dir`. The CI is GitHub Actions, if Task 1 confirms GitHub.

**Spec:** [`Hearth a Rust framework for Durable Object game servers.md`](../../../Hearth%20a%20Rust%20framework%20for%20Durable%20Object%20game%20servers.md), sections Goals (prototype in under an hour, self-hostable), Client SDKs (distribution rows), Roadmap v1.0 ("docs site, three shipped sample games"), and Open questions (Unity licence, naming). **Builds on:** every earlier plan, especially [v1.0a](2026-10-25-hearth-v1.0a-freeze.md) (`check-stability.sh`, `bundle-size.sh`, the conformance kit).

## Global Constraints

- All earlier Global Constraints still apply. `scripts/check-stability.sh` must pass at every commit in this plan.
- Distribution (spec): Godot through the Asset Library; Unity as a UPM git package and on OpenUPM. The Asset Store is a user decision (Task 2).
- Licence: `MIT OR Apache-2.0` for every Hearth artifact. Shipped native binaries (the GDExtension and Unity plugins) must include third-party notices for every bundled Rust dependency.
- **One version everywhere.** The Rust crates, the Unity `package.json`, the Godot `plugin.cfg`, the CLI and the templates' dependency versions all carry the same `X.Y.Z`, and a test enforces it.
- **A rename changes user-facing identifiers only.** That means crate and package names, the CLI binary, docs, namespaces and class prefixes. The frozen wire constants keep `hearth`: `hearth:ping`, `hearth.*` events, the `X-Hearth-*` headers, `/__hearth/*`, the `hearth_*` SQL tables, and `hearth_schema` in SchemaDoc. Protocol v1 was frozen in v1.0a, and these strings are part of it.
- Nothing outward-facing happens without the user's explicit yes in chat, given for that specific action: creating repos or orgs, publishing to any registry, pushing tags, deploying the site, submitting to stores, or registering domains or trademarks.
- **No legal advice.** Task 1 gathers availability facts and points to the official trademark search tools, and recommends that the user consult a lawyer before relying on a name.

## Review Focus

1. **Irreversible publishes.** A crates.io version cannot be deleted, only yanked. Every registry gets a full dry-run first, with crates published in dependency order, versions checked for consistency, and a separate user approval per registry. A failure midway must leave a clear resume point and never a half-published, unusable set. Tests are in Tasks 6 and 7.
2. **The rename touching frozen wire constants.** The rename script must keep the exclusion list above. The conformance kit, every e2e suite and `check-stability.sh` must pass after a rename, and the wire-constant snapshot must be unchanged. Tests are in Task 1.
3. **Licence violations in shipped binaries.** A copyleft dependency (GPL or AGPL) bundled into the Unity or Godot plugin, or missing notices. `cargo deny check licenses` must pass, and every binary archive must contain `THIRD_PARTY_NOTICES.html`. Tests are in Task 2.
4. **Template rot.** A template that only works from inside the repo (path deps, a missing file in `include_dir`). Each template must be generated by the **built CLI binary** into a temp dir outside the repo, then built and tested there. Tests are in Task 3.
5. **Secrets or junk in published packages.** `.dev.vars`, `target/`, test keys from the e2e scripts. Each package's file list is checked against an allowlist before publishing. Tests are in Task 6.

### Task 2: Licensing, notices, and package metadata

**Files:**
- Create: `deny.toml`, `about.toml`, `about.hbs`
- Modify: every `crates/*/Cargo.toml` (`description`, `repository`, `homepage`, `documentation`, `readme`, `keywords` ≤ 5, `categories`, `rust-version`, and `license = "MIT OR Apache-2.0"` already set); `unity/com.hearth.client/package.json` (`author`, `license`, `repository`, `documentationUrl`, `changelogUrl`, `licensesUrl`); `godot/addons/hearth/plugin.cfg` and a new `godot/addons/hearth/LICENSE`
- Modify: `scripts/build-unity-native.sh` and the GDExtension build (put `THIRD_PARTY_NOTICES.html` next to the binaries)
- Create: `docs/release/unity-store.md`

**Interfaces:**
- Consumes: the dependency graph of every shipped binary (`hearth-unity-plugin`, `hearth-godot`, and the CLI).
- Produces:
  - `deny.toml` allows `MIT`, `Apache-2.0`, `Apache-2.0 WITH LLVM-exception`, `BSD-2-Clause`, `BSD-3-Clause`, `ISC`, `Zlib`, `Unicode-3.0`, `Unicode-DFS-2016` and `MPL-2.0` (file-level copyleft, acceptable for binary distribution with notices). It denies `GPL-*`, `AGPL-*`, `LGPL-*` and unknown licences, and bans duplicate major versions only as a warning. The advisories check is on.
  - `cargo about generate about.hbs -o THIRD_PARTY_NOTICES.html` runs per shipped binary crate (`-m crates/<crate>/Cargo.toml`). The build scripts copy the output into `godot/addons/hearth/` and `unity/com.hearth.client/` (Unity's `Third Party Notices.md` convention: generate both HTML and MD from the template).
  - `docs/release/unity-store.md` sets out the options for the Asset Store question, as facts for the user to decide on: UPM and OpenUPM only; the Asset Store under the Standard Unity Asset Store EULA, with the MIT/Apache sources still available on GitHub; or the Asset Store with a dual-licence notice. It links the Asset Store provider terms. The plan does not recommend an option, because licensing is the user's call.

- [ ] **Step 2: Generate the notices and wire them into both build scripts.** Run each build. **Expected: `THIRD_PARTY_NOTICES.html` is next to every produced binary** (Review Focus 3).

    - a Rust workspace test on Linux, Windows and macOS;
    - the wasm builds;
    - `check-stability.sh`, which includes the versions and the bundle size;
    - `cargo deny`;
    - `mdbook build` and `mdbook test`;
    - the templates test with `HEARTH_REQUIRE_ENGINES=0`;
    - Godot headless tests in a container with Godot pinned to 4.3 (official or community image; pin its digest);
    - the conformance Rust runner.

    The Unity tests are a manual or self-hosted job, documented in the checklist, because they need a licence.
  - `release.yml` runs on a `v*` tag. It builds the native matrix (Windows, Linux, macOS universal, Android and iOS on macOS runners, WebGL), runs both packaging scripts, generates the notices, and creates a **draft** release with `dist/*` attached and the changelog section as the body. It never publishes to registries. Publishing stays manual and gated (Task 7).
  - `docs/release/checklist.md` is the runbook. It lists every step from `release.sh` to the registries, with the approval each step needs.

### Task 6: Publish dry-runs and package content checks

**Files:**

- Test: the scripts themselves

**Interfaces:**
- Consumes: Tasks 2 and 5.
- Produces:
  - `scripts/publish-crates.sh [--dry-run] [--from <crate>]` computes the publish order from `cargo metadata` with a topological sort over intra-workspace dependencies, and skips `publish = false` crates (examples, bench, the conformance server unless the user wants it published; ask in Task 7). For each crate it runs `cargo publish -p <crate> [--dry-run]` and waits for the crates.io index to show the version before moving on (poll `cargo search`, timeout 5 min). `--from` resumes after a failure (Review Focus 1).   - Package allowlists. The rules:
    - `cargo package --list -p <crate>` for every crate, plus the contents of the Godot zip and the Unity tgz, must match the glob allowlists.
    - Any `.dev.vars`, `*.pem`, `*.key`, `target/`, `node_modules/` or `results.json`, or a file over 5 MB (apart from the allowlisted native binaries), fails with the offending path (Review Focus 5).
    - Exclude test JWT and JWKS material from the e2e scripts through `exclude` in `Cargo.toml` and through `.npmignore`.
  - `scripts/check-packages.sh` runs every allowlist check and is called by `release.sh` before it stops.
