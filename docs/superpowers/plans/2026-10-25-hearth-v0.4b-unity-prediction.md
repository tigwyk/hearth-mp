# Hearth v0.4b (Unity Prediction) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Unity games can predict their own player with the same shared Rust logic crate as the server, compiled into the Unity native plugin (spec: "Optional: shared logic crate in the native plugin"). This brings Unity level with the Godot arena sample from v0.4, on desktop, mobile and WebGL.

**Architecture:** `hearth-unity` is split into an rlib (implementation plus a `plugin!` macro) and a stock cdylib crate that only calls `plugin! {}`. A game that wants prediction builds its own cdylib, also named `hearth_unity`, with `plugin! { logic: { "arena" => arena_logic::Arena } }`. The macro emits every existing Hearth export plus a fixed set of `hearth_predictor_*` exports that dispatch by logic name to an object-safe `DynPredictor`. Because the export names are fixed, one C# `HearthPredictor<TState>` and one jslib serve every game, and no per-game codegen is needed. The predicted state flows into the v0.2b typed mirror, so the predicted avatar gets the same `OnChange` events as the authoritative state.

**Tech Stack:** As in v0.2b and v0.4.

**Spec:** [`Hearth a Rust framework for Durable Object game servers.md`](../../../Hearth%20a%20Rust%20framework%20for%20Durable%20Object%20game%20servers.md), Client SDKs table (Prediction row). **Builds on:** [v0.2b](2026-10-25-hearth-v0.2b-unity.md) (the Unity package, FFI, WebGL bridge and typed mirror) and [v0.4](2026-10-25-hearth-v0.4-ticked-rooms.md) (the `Logic` trait, `Predictor`, `arena-logic`, the arena server, interpolation). Names this plan does not redefine are as defined there.

## Global Constraints

- All earlier Global Constraints still apply.
- The native library name stays `hearth_unity`, and on iOS P/Invoke uses `"__Internal"`, so a custom plugin is a drop-in replacement for the stock binaries.
- Every predictor export catches unwinds and never aborts Unity (the v0.2b Review Focus 1 rule applies to dev logic too).
- The stock plugin includes exactly one built-in logic, `"hearth.echo1d"`: a 1-D counter that the package tests and the docs use. Nothing else of the dev's ships in the stock binaries.
- The prediction contract is unchanged from v0.4: the client records the input with the exact seq that `Send` returned, rebuilds from authoritative state on each patch or ACK, and replays the unacked inputs one fixed step each.
- **Out of scope:** Unity-specific smoothing helpers (smoothing stays in sample code, as in Godot) and predicting other players.

## Review Focus

1. **No logic in the plugin, or a wrong name.** The stock plugin, or a typo in `"arnea"`, must throw `HearthException("PREDICTOR_UNAVAILABLE", "...rebuild the native plugin with plugin! { logic: { \"arnea\" => ... } }")`. It must never surface `EntryPointNotFoundException` or crash. Tests are in Task 3.
2. **Logic state that doesn't match the room view** (the logic crate and the room `State` drift apart). Deserialisation fails, so the predictor disables itself, raises `OnError` **once**, and `State` falls back to the authoritative state. It must not throw every frame. Tests are in Tasks 2 and 3.
3. **A panic in the dev's `step`.** It must be caught at the FFI boundary. The predictor is then poisoned, reports once, and falls back as in point 2. Tests are in Task 2.
4. **Seq mismatch.** An input sent while disconnected, or delayed by the send-rate cap, must keep the seq that `Send` returned, so later ACKs drop exactly the right inputs. Tests are in Task 3.
5. **Teardown order.** If the room or client is destroyed before the predictor, the predictor must unsubscribe and free its handle exactly once, and must not fire callbacks afterwards. Tests are in Task 3.

### Task 2: `DynPredictor` and the predictor exports

**Files:**
- Modify: `crates/hearth-client/src/predict.rs`
- Modify: `crates/hearth-unity/src/lib.rs` (the predictor part of `plugin!` and `ffi::__impl_predictor_*`)
- Test: `crates/hearth-client/tests/predict.rs` (extend), `crates/hearth-unity-plugin/tests/predictor.rs`, `tests/web.rs` (extend)

**Interfaces:**
- Consumes: `Logic` and `Predictor<L>` (v0.4).
- Produces:
  - `pub trait DynPredictor { fn input(&mut self, seq: u32, input: &Value) -> Result<(), String>; fn on_authoritative(&mut self, state: &Value, acked: &[u32]) -> Result<(), String>; fn on_unconfirmed(&mut self, seqs: &[u32]); fn predicted(&self) -> Result<Value, String>; }`, implemented for `Predictor<L>` with `serde_json` conversions. A conversion failure returns `Err` with the serde message.
  - `pub fn boxed<L: Logic + 'static>(me: PlayerId, tick_hz: u8) -> Box<dyn DynPredictor>`
  - `pub struct Echo1d;`, the built-in logic: `State = { "x": i64 }` (it deserialises from `{"x": n}`, and other fields are ignored), `Input = i64` (clamped to -1..=1), and `step` adds the input. Its registered name is `"hearth.echo1d"`.
  - Predictor exports (emitted by `plugin!`):
    - `hearth_predictor_new(logic: *const c_char, me: *const c_char, tick_hz: u8) -> *mut HearthPredictor` (null on an unknown name; the last error is set to `unknown logic "<name>"; registered: [..]`)
    - `hearth_predictor_free(p)`
    - `hearth_predictor_input(p, seq: u32, input_json) -> u8` (1 = ok)
    - `hearth_predictor_on_authoritative(p, state_json, acked_json /*JSON u32 array*/) -> u8`
    - `hearth_predictor_on_unconfirmed(p, seqs_json)`
    - `hearth_predictor_state(p) -> HearthBuf` (JSON; empty on error)
    - `hearth_predictor_names() -> HearthBuf` (a JSON array of the registered names)
  - Poisoning: a `HearthPredictor` holds `Box<dyn DynPredictor>` plus `poisoned: Option<String>`. Any `Err` or caught panic sets `poisoned`. After that every call returns 0 or empty and the last error is the poison message. C# reads it once (Task 3).
  - The wasm exports mirror these with a `u32` handle, as in v0.2b Task 6: `predictor_new(logic, me, hz) -> u32` (0 = error), and so on.

### Task 3: C# `HearthPredictor<TState>`

**Files:**
- Create: `unity/com.hearth.client/Runtime/Predict/HearthPredictor.cs`
- Modify: `Runtime/Core/IHearthCore.cs`, `NativeCore.cs`, `WebGLCore.cs`, `Plugins/WebGL/hearth.jslib`
- Test: `Tests/Editor/PredictorTests.cs`, plus `Tests/Editor/Generated/Echo1dState.cs` (a hand-written typed class `{ X: long }` in the codegen format, used only by tests)

**Interfaces:**
- Consumes: the Task 2 exports; `HearthRoom` (`Send`, `OnPatched`, `OnAck`, `OnIntentsUnconfirmed`, `RawState`, `PlayerId`); the typed mirror (`HearthNode.Load`).
- Produces:
  - `public sealed class HearthPredictor<TState> : IDisposable where TState : HearthNode, new()`:
    - `public HearthPredictor(HearthRoom room, string logicName, int tickHz)`. It throws `HearthException("PREDICTOR_UNAVAILABLE", msg)` when the native entry point is missing (catch `EntryPointNotFoundException` and `DllNotFoundException`) or when `new` returns null; the message includes `hearth_predictor_names()` when available (Review Focus 1). It subscribes to the room's `OnPatched` (→ `on_authoritative(RawState, [])`), `OnAck` (→ `on_authoritative(RawState, intentSeqs)`) and `OnIntentsUnconfirmed`.
    - `public uint Input(JToken intent)`: `var seq = room.Send(intent);`, then `predictor_input(seq, intent)`. It returns `seq` (Review Focus 4).
    - `public TState State { get; }`: a typed instance reloaded from `hearth_predictor_state` after each `Input` and each authoritative update. When the predictor is poisoned, it is reloaded from `room.RawState` instead.
    - `public bool Poisoned { get; }` and `public event Action<string> OnError`, which fires once at the moment of poisoning (Review Focus 2).
    - `Dispose()` unsubscribes from the room and frees the `SafeHandle`. It is idempotent. The predictor also disposes itself when the room raises `OnDisconnected` with a give-up close or when the client is destroyed, and fires no events after that (Review Focus 5).
  - `IHearthCore` gains `IntPtr`-free predictor methods, so `WebGLCore` can implement them through the jslib functions `HearthPredictor_New/Free/Input/OnAuthoritative/OnUnconfirmed/State/Names`. These use the same length-query-then-copy protocol as v0.2b.
